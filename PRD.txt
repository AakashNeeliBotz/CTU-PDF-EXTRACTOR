Product Requirements Document (PRD): Automated PDF Data Extraction & Consolidation
Project Title: CTU - Automated PDF Data Extraction and Consolidation (Pilot Phase)

1. Problem Statement
Key decision-making in the energy sector relies on timely and accurate data from various government bodies, such as the Central Transmission Utility of India (CTU). This data is frequently published in PDF documents across multiple websites, often on a daily or weekly basis. The current process of manually downloading these PDFs, extracting the relevant information, and consolidating it into a structured Excel sheet is time-consuming, prone to human error, and inefficient. This manual bottleneck delays insights and increases operational overhead. The challenge is compounded by the variety of PDF formats (digital and scanned) and the inconsistent data structures within them.

2. Project Goal & Vision
The ultimate vision is to create a fully autonomous, reliable data pipeline that eliminates the manual effort involved in this process. This system will automatically monitor multiple government websites, download new and historical PDF documents, intelligently extract structured data using a Generative AI model, and populate a master Excel sheet in a predefined format.

This document outlines the Pilot Phase, which aims to prove the viability of this vision by building a functional end-to-end solution for a limited set of data sources.

3. Scope (Pilot Phase)
3.1. In-Scope Features
Target Data Sources: The pilot will focus exclusively on the following 6 data sources as listed in the project documentation:

SN 3: Status of effectiveness of connectivity granted to RE generators (Daily)

SN 4: CTU Re-allocation meetings (Agenda and Minutes) (Weekly)

SN 5: CTU Bidding Calendar (Weekly)

SN 6: CEA TBCB report from CEA transmission (Daily)

SN 7: CTUIL (OPEN ACCESS) Compliance of Land and Financial Closure (Daily)

SN 8: Monitoring of Connectivity (all 3 Annexures) (Daily)

Primary URL: The initial crawling entry point will be https://www.ctuil.in/regenerators and other relevant pages where the links for the above sources are located.

Automated Web Crawling & Downloading: The system will crawl the target pages, identify all hyperlinks pointing to .pdf files, and download them.

PDF Processing: The solution must handle both digital (text-based) and scanned (image-based) PDFs.

LLM-Based Data Extraction: A locally-hosted, open-source Large Language Model (LLM) will be used to extract structured data from the text content of the PDFs.

Data Consolidation: The extracted, structured data (in JSON format) will be saved into a final Excel sheet, mapping the data to the correct columns as specified in the Connectivity Application Data.xlsx template.

Historical Data: The solution should be capable of downloading and processing all currently available PDFs from the in-scope sources.

3.2. Out-of-Scope (for Pilot)
Full Set of 17 Sources: The remaining 11 data sources are out of scope for this pilot.

User Interface (UI): No graphical user interface will be developed in this phase. The solution will be a script or a collection of scripts run from the command line.

Cloud Deployment: The entire solution will be designed to run on a local machine/server.

Advanced Error Handling & Monitoring Dashboard: While basic logging will be implemented, a sophisticated monitoring dashboard is not in scope.

4. Technical Stack & Architecture
This solution will be built as a modular Python application.

Core Language: Python 3.10+

Web Crawler: Crawl4AI (to find PDF links and convert web content to Markdown).

PDF Downloader: requests or httpx (for robustly downloading the files).

PDF Text Extraction (Digital): PyMuPDF (or fitz).

OCR for Scanned PDFs: Tesseract via the pytesseract Python wrapper.

Large Language Model: A locally hosted open-source model. Microsoft's Phi-3-mini-instruct is recommended due to its excellent performance, efficiency, and instruction-following capabilities.

LLM Serving Framework: Ollama (for ease of setup and use).

Data Manipulation & Excel Generation: pandas and openpyxl.

Orchestration/Scheduling: APScheduler (Python library) or a system cron job.

System Architecture Workflow
Crawl: The Crawl4AI module is initiated to scan the target URLs. It identifies all PDF links.

Download: The list of PDF URLs is passed to the downloader module, which fetches and saves the PDF files locally.

Process: Each PDF is classified as "digital" or "scanned". Text is extracted directly or via OCR.

Extract: The raw text from the PDF is sent as a payload to the local Ollama API endpoint serving the LLM. A carefully crafted prompt instructs the model to return a structured JSON with the required data fields.

Consolidate: The JSON output from the LLM is parsed. The pandas module reads the Excel template, appends the new data to the appropriate DataFrame/sheet, and saves the updated Excel file.

Schedule: The entire process is wrapped in a main script and scheduled to run at specified intervals (e.g., daily).

5. Development & Implementation Plan
This plan is designed to be executed by an agentic development environment.

Phase 1: Environment Setup & Configuration
Initialize Project: Create a new Python project with a virtual environment.

Install Dependencies: Install all Python libraries specified in the tech stack (crawl4ai, requests, pymupdf, pytesseract, pandas, openpyxl, ollama, apscheduler).

Setup LLM: Install Ollama on the local machine. Pull the required model using the command: ollama pull phi3.

Configuration File: Create a config.py or config.json file to store constants like target URLs, download paths, and the Excel template path.

Phase 2: Scraper and Downloader Module
Create scraper.py:

Implement a function that takes a URL as input.

Use Crawl4AI to crawl the URL.

Parse the output to find all unique URLs ending in .pdf.

Return a list of these PDF URLs.

Create downloader.py:

Implement a function that takes a list of PDF URLs and a download directory.

Loop through the URLs, download each file using requests, and save it to the directory.

Implement logic to avoid re-downloading existing files.

Phase 3: PDF Processing Module
Create pdf_processor.py:

Implement a function extract_text_from_pdf(pdf_path).

Inside this function, first, try to extract text using PyMuPDF.

If the extracted text is minimal or nonsensical (indicating a scanned PDF), fall back to using pytesseract to perform OCR on the PDF images.

The function should return the full, cleaned text of the document as a single string.

Phase 4: LLM Extraction Module
Create llm_extractor.py:

Implement a function extract_structured_data(text).

This function will contain the prompt engineering. The prompt should instruct the LLM to act as a data extraction expert and return a JSON object containing specific fields based on the content of the text. Initial prompt development will be crucial.

The function will make a POST request to the local Ollama server endpoint (http://localhost:11434/api/generate).

It will parse the LLM's response to get the JSON output.

Implement error handling for malformed JSON.

Phase 5: Data Consolidation Module
Create excel_handler.py:

Implement a function update_excel(data, template_path, output_path).

Use pandas to read the specified sheet from the Excel template file.

Append the structured data (likely a list of dictionaries) to the DataFrame.

Use pandas.ExcelWriter or to_excel() to save the updated DataFrame to the output path, ensuring the template's formatting is preserved as much as possible.

Phase 6: Main Orchestration Script
Create main.py:

Import functions from all other modules.

Define the end-to-end workflow:

Call the scraper to get PDF links.

Call the downloader to save the PDFs.

Iterate through each downloaded PDF.

For each PDF, call the processor to get its text.

Send the text to the LLM extractor to get structured JSON.

Collect all the JSON data.

Call the Excel handler to update the final report.

Add Scheduling: Use APScheduler to configure the main.py script to run on a daily schedule.

6. Success Metrics
Data Accuracy: The data extracted by the LLM and populated in the Excel sheet must have an accuracy of >95% compared to a manual check.

Automation Reliability: The automated script must run successfully on its schedule without manual intervention for 99% of its runs.

Completeness: The system successfully downloads and processes all available PDF documents (both historical and new) from the in-scope sources.

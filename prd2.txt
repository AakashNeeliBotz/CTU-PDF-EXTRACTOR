Project Brief: CTU Automated PDF Data Extraction (Refactored)

1. Initial Goal

The primary objective is to create a fully automated pipeline to download PDF documents from various Indian government energy sector websites, extract specific data from them using a local Large Language Model (LLM), and consolidate this structured data into a multi-sheet Excel report.

2. Evolution of the Architecture

The project has evolved significantly from the initial proof-of-concept to a robust, configuration-driven system.

Initial Approach (Now Deprecated): The first version of the pipeline was a simple, linear process. It scraped a few hardcoded links, downloaded all PDFs into a single folder, and used a single, powerful LLM prompt to extract data for just one target Excel sheet.

Key Refinement: It was determined that the target Excel file contains multiple sheets (e.g., "RE Potential," "Margin," "Element Status"). Each sheet requires data from a different combination of source websites and needs a unique set of fields extracted.

Final Architecture ("Sheet-First" Model): The entire system was refactored to be "sheet-aware." The pipeline is now driven by a central configuration that maps specific data sources and custom extraction prompts to their corresponding target Excel sheets.

3. Final System Architecture & Workflow

The current implementation is a modular, multi-phase system orchestrated by main.py. The logic is governed by two new configuration files: config.py and prompts.py.

Core Components:

config.py (The Brain): This is the master configuration file.

DATA_SOURCES: A dictionary mapping every unique source ID (e.g., SN1, SN10a) to its specific URL.

SHEET_CONFIG: A dictionary where each key is the name of a target Excel sheet. The value specifies which source IDs (sources) are needed for that sheet and which LLM prompt (prompt_name) to use.

prompts.py (The Prompt Library): This file contains a dictionary of multiple, highly-specific system prompts. Each prompt is expertly crafted to instruct the LLM to extract the exact columns required for a single Excel sheet.

Execution Flow (Orchestrated by main.py):

Initialization: The OCR (Nanonets-OCR-s) and LLM (gemma-3n-E4B-it) models are loaded into memory once for efficiency.

Phase 1: Scrape & Download: The script iterates through config.DATA_SOURCES. It scrapes every URL and downloads all found PDFs into a structured directory system (e.g., downloaded_pdfs/SN1/, downloaded_pdfs/SN2/, etc.). This creates an organized, persistent link between each file and its origin.

Phase 2: Process Sheet-by-Sheet: The script then iterates through config.SHEET_CONFIG.

For each sheet (e.g., "Element Status"), it identifies the required source folders (e.g., SN1, SN2, SN5...).

It processes every PDF within those specific folders.

For each PDF, it extracts the raw text using the pdf_processor.

It then sends this text to the LLM using the correct, context-specific prompt (e.g., PROMPT_ELEMENT_STATUS from prompts.py).

Phase 3: Write to Excel: The structured data returned by the LLM is collected. After all relevant PDFs for a sheet have been processed, the excel_handler writes the complete dataset to the corresponding sheet in the output Excel file. This loop continues until all sheets defined in the config have been populated.

Technology Stack:

Scraping: requests & BeautifulSoup for targeted, reliable link finding.

PDF Text Extraction: PyMuPDF for digital text and nanonets/Nanonets-OCR-s (via transformers) for robust OCR on scanned documents.

LLM Inference Engine: llama-cpp-python for high-performance, local inference on CPU/GPU.

LLM: unsloth\gemma-3n-E4B-it-GGUF 

Excel Handling: pandas and openpyxl for writing data to the multi-sheet template.

4. Actionable Instructions

To execute the project, use the provided set of 8 Python files.

Setup:

Ensure all Python scripts are in the same root directory.

Place the Excel template Connectivity Application Data.xlsx in the root directory.

Create a subfolder named models.

Download the gemma-3n-4b-e4b-it.Q4_K_M.gguf model file and place it inside the models folder.

Execution:

The sole entry point for the entire pipeline is main.py.

Run the command: python main.py.
